# Динамично програмиране

## 1. Какво е DP?

**Динамичното програмиране (DP)** е техника, при която сложен проблем се разбива на **по-малки подзадачи**. Всяка подзадача се решава **само веднъж**, а резултатът ѝ се **запомня** и се използва повторно всеки път, когато е нужен.

### Пример: Fibonacci

```cpp
long long fib(int n) {
    if (n < 2) {
        return n;
    }

    return fib(n - 1) + fib(n - 2);
}
```

`fib(5)` вика `fib(4)` и `fib(3)`; `fib(4)` вика `fib(3)` и `fib(2)` и т.н. — `fib(3)` се пресмята **няколко пъти**. Дървото на извикванията расте експоненциално: **O(2ⁿ)**.

Различните подзадачи обаче са само `n + 1` (`fib(0) … fib(n)`). Ако всяка я решим веднъж и запомним отговора, получаваме **O(n)**.

---

## 2. Кога е приложимо DP?

1. **Оптимална подструктура** — отговорът за цялата задача се получава от оптималните отговори на по-малки подзадачи от същия вид.
2. **Повтарящи се подзадачи** — едни и същи подзадачи се срещат многократно, затова си струва да запомним резултата им.

## 3. Top-Down vs Bottom-Up

### 3.1 Top-Down (Memoization)

Пишеш проблема **рекурсивно**, точно както би го написал без DP: започваш от търсения отговор (голямата задача) и я разбиваш на по-малки подзадачи, докато стигнеш до базата — случай, чийто отговор се знае директно.

Единствената добавка към обикновената рекурсия е **кешът** — масив `dp`, в който пазим вече пресметнатите резултати. За всяко извикване на функцията:

1. Ако състоянието е **база** → връщаш отговора директно.
2. Ако `dp[state]` вече е изчислено → връщаш кешираната стойност, без да рекурсираш.
3. Иначе го **пресмяташ** чрез рекурсивните извиквания, **записваш** резултата в `dp[state]` и го връщаш.

Нужна е специална стойност, която означава „още не е пресметнато“. Тя трябва да е различна от всеки възможен отговор.

Така всяко състояние се пресмята най-много веднъж, а се изчисляват само онези състояния, до които рекурсията наистина стига.

```cpp
long long fib(int n) {
    static long long dp[100]{};

    if (n < 2) {
        return n;
    }

    if (dp[n] != 0) {
        return dp[n];
    }

    dp[n] = fib(n - 1) + fib(n - 2);
    return dp[n];
}
```

### 3.2 Bottom-Up (Tabulation)

Пишеш **итеративно**, без рекурсия: започваш от най-малките подзадачи и с цикъл надграждаш към по-големите, докато стигнеш до търсения отговор. Резултатите се пълнят в таблица `dp`.

Стъпките са:

1. **Създаваш таблицата** `dp` с размер, който покрива всички състояния.
2. **Попълваш базата** — клетките, чийто отговор се знае директно.
3. **Обхождаш състоянията в правилен ред** с цикъл: когато стигнеш до дадена клетка, всички клетки, от които тя зависи, трябва вече да са пресметнати. Посоката на цикъла следва посоката на зависимостите.
4. **Пресмяташ всяка клетка** по рекурентната зависимост от вече готови клетки.
5. **Взимаш отговора** от крайната клетка (`dp[n]`).

За разлика от memoization тук се пресмятат **всички** състояния, независимо дали са нужни, но няма рекурсия и затова няма риск от препълване на стека.

```cpp
long long fib(int n) {
    if (n < 2) {
        return n;
    }

    vector<long long> dp(n + 1);

    dp[0] = 0;
    dp[1] = 1;

    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }

    return dp[n];
}
```

## 4. Стъпки за решаване

1. **Определи state — какво пази всяка клетка.** Какво означава `dp[i]`? Напр. „`dp[i]` = най-малкият брой монети за сума `i`“.

2. **Напиши рекурентната зависимост.** Дефинирай как се изразява текущата клетка от по-малките клетки: от кои зависи `dp[i]` и как се получава от тях.

3. **Задай базата.** Запиши отговорите на най-малките подзадачи — тези, които се решават директно, без да зависят от други. Останалите клетки получават начална стойност, която не пречи на пресмятането.

4. **Определи къде е отговорът.** Обикновено `dp[n]`, но понякога е `max(dp)` или друга клетка.

**Бонус: спести памет.** Често за изчисляването на една клетка са нужни само няколко предишни, а не цялата таблица. Тогава пазиш само тях и презаписваш старите стойности.

Примери:
   - едномерна таблица → няколко променливи (за Fibonacci стигат последните две числа)
   - двумерна таблица → само предишният и текущият ред
