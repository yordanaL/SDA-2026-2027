# Алгоритми за търсене

## 1. Linear Search

**Концепция:** Линейното търсене е най-простият възможен алгоритъм — обхождаме масива елемент по елемент от началото до края и сравняваме всеки елемент с търсената стойност. При първото съвпадение връщаме индекса. Ако стигнем края без съвпадение, елементът липсва.

Не се изисква масивът да е сортиран — алгоритъмът работи върху произволни данни.

Анимация на Linear Search за елемент `9` в масива `{4, 2, 7, 1, 9, 3}`:

![Linear Search анимация](images/linear_search.svg)

Код:

```cpp
#include <vector>

int linearSearch(const std::vector<int>& v, int target) {
    for (int i = 0; i < (int)v.size(); i++) {
        if (v[i] == target) {
            return i;
        }
    }
    return -1;
}
```

Сложност:

| време (най-лош) | памет |
| :--- | :--- |
| $O(N)$ | $O(1)$ |

## 2. Binary Search

**Концепция:** Двоичното търсене е много по-ефективен алгоритъм, но работи само върху сортиран масив. Идеята е, че на всяка стъпка сравняваме търсения елемент с елемента по средата на текущия диапазон. Ако търсеният елемент е по-малък, продължаваме търсенето в лявата половина. Ако е по-голям, продължаваме в дясната половина. Процесът се повтаря, докато елементът бъде намерен или диапазонът за търсене се изчерпи.

Така при всяка стъпка броят на елементите, които трябва да бъдат проверени, намалява наполовина, което прави алгоритъма значително по-бърз от линейното търсене.

Анимация на Binary Search за елемент `11` в масива `{1, 3, 5, 7, 9, 11, 13, 15}`:

![Binary Search анимация](images/binary_search.svg)

Код (итеративна реализация):

```cpp
#include <vector>

int binarySearch(const std::vector<int>& v, int target) {
    int left = 0;
    int right = (int)v.size() - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;

        if (v[mid] == target) {
            return mid;               
        } 
        else if (v[mid] < target) {
            left = mid + 1;  
        } 
        else {
            right = mid - 1;
        }
    }

    return -1;   
}
```

Сложност:

| време | памет (итеративна) |
| :--- | :--- |
| $O(\log N)$ | $O(1)$ |

---


### Формули за изчисляване на mid

При двоичното търсене изчисляваме средния индекс по два начина:

### Формула 1: `mid = (left + right) / 2`

```cpp
int mid = (left + right) / 2;
```

### Формула 2: `mid = left + (right - left) / 2`

```cpp
int mid = left + (right - left) / 2;
```

### Коя е по-добра и защо?

Формула 2 е по-добрата.

Причината е препълване на целочисления тип (integer overflow). Ако `left` и `right` са големи (например близки до `INT_MAX = 2147483647`), сумата `left + right` може да надхвърли максималната стойност на `int`. Когато това се случи, стойността „превърта“ и получаваме отрицателно число — от което `mid` излиза извън диапазона $[left, right]$.

---

### Кой е по-подходящ: Linear или Binary Search?

* Върху сортиран масив Binary Search е значително по-добър. Причината е в броя на сравненията. 

    Нека масивът има $N = 10^6$ елемента:
    * Linear Search в най-лошия случай прави $10^6$ сравнения.
    * Binary Search прави най-много $\log_2 10^6 \approx 20$ сравнения.

    Двоичното търсене използва информацията, че масивът е подреден, за да „изхвърля“ по половината от оставащите елементи на всяка стъпка. Затова когато данните вече са сортирани, Binary Search е естественият избор.

* Ако търсението е единично върху несортиран масив е по-оптимално да използваме Linear Search ($O(N)$). Самото сортиране($O(N \log N)$), за да използваме Binary Search би било по-бавно от самото линейно търсене.

* Ако ще правим много търсения върху един и същ масив си струва първо да сортираме ($O(N \log N)$) и след това да прилагаме Binary Search за всяка търсено число.

### lower_bound и upper_bound

(!вградените функции lower_bound и upper_bound имат малко по-различно поведение от долупосочените имплементации!)

* Binary Search за намиране на индекса на първия елемент, който е по-голям или равен на target:

```cpp
#include <vector>

int lowerBound(const std::vector<int>& v, int target) {
    int left = 0;
    int right = (int)v.size() - 1;
    int ans;             

    while (left <= right) {                  
        int mid = left + (right - left) / 2;

        if (v[mid] >= target) {
            right = mid - 1;  
            ans = mid;             
        }
        else {
            left = mid + 1;                    
        }
    }

    return ans;
}
```

* Binary Search за намиране индекса на последния елемент, който е по-малък или равен на target:

```cpp
#include <vector>

int upperBound(const std::vector<int>& v, int target) {
    int left = 0;
    int right = (int)v.size() - 1;
    int ans;             

    while (left <= right) {                  
        int mid = left + (right - left) / 2;

        if (v[mid] <= target) {
            left = mid + 1;  
            ans = mid;             
        }
        else {
            right = mid - 1;                    
        }
    }

    return ans;
}
```

**Примери** за `v = {1, 3, 5, 7, 9, 11, 13, 15}`:

* `lowerBound(v, 5)` → `2`, защото търсим първия елемент `≥ 5`, а самият `5` стои на индекс `2`.
* `lowerBound(v, 6)` → `3`, защото `6` не съществува в масива, но първият елемент `≥ 6` е `7` на индекс `3`.
* `upperBound(v, 5)` → `2`, защото търсим последния елемент `≤ 5`, а самият `5` стои на индекс `2`.
* `upperBound(v, 6)` → `2`, защото `6` не съществува, а последният елемент `≤ 6` е `5` на индекс `2` (`7` вече е твърде голямо).

С дубликати `v = {1, 2, 2, 2, 5}`: `lowerBound(v, 2)` → `1` (първото `2`), `upperBound(v, 2)` → `3` (последното `2`) — т.е. двете заедно дават границите на всички срещания на `2`.

**Брой срещания:** понеже `lowerBound` връща индекса на първото срещане, а `upperBound` — на последното, броят на срещанията на `x` се изчислява като:

```cpp
int count = upperBound(v, x) - lowerBound(v, x) + 1;
```
**!работи само ако x присъства във вектора!**

С `v = {1, 2, 2, 2, 5}` и `x = 2`: `count = 3 - 1 + 1 = 3`. Ако `x` се среща веднъж, границите съвпадат и формулата дава `1`. Ако `x` липсва, резултатът не е надежден.

### Binary Search over the Answer (двойчно търсене по отговора)

**Концепция:** Двоично търсене по отговора е техника, при която търсим минимална или максимална числова стойност, която удовлетворява дадено условие, вместо да търсим директно елемент в масив. 

Идеята е да изберем средна стойност mid от диапазона с възможни отговори и да проверим дали тя е валидна чрез функция check(mid). Ако търсим минималния валиден отговор и проверката връща true, запазваме mid като потенциален отговор и продължаваме да търсим наляво, защото може да има по-малка валидна стойност. Ако проверката връща false, търсим надясно, защото по-малките стойности също няма да са валидни. 

За да работи техниката, проверката трябва да е монотонна — резултатите да се променят само веднъж, например от false към true. При търсене на максимален валиден отговор логиката е обратната.

Техниката се използва например в задачи за намиране на минимална скорост, време или капацитет, както и на максимална възможна дължина. Основното ѝ предимство е, че при всяка стъпка елиминираме половината от оставащите възможности, вместо да проверяваме всички стойности последователно.

## 3. Ternary Search

**Концепция:** Тернарното търсене е разширение на двоичното — вместо на две, диапазонът се дели на три почти равни части чрез две междинни индекса `m1` и `m2`. Сравняваме търсената стойност с елементите на двата междинни индекса и изключваме една от трите части:

* Ако `target < a[m1]` → търсеното е в левата част (индекси $[left, m1-1]$).
* Ако `target > a[m2]` → търсеното е в дясната част (индекси $[m2+1, right]$).
* Иначе търсеното е в средната част (индекси $[m1+1, m2-1]$).

Анимация на Ternary Search за елемент `8` в масива `{1, 2, 3, 4, 5, 6, 7, 8, 9}`:

![Ternary Search анимация](images/ternary_search.svg)

Сложност:

| време (най-лош) | памет |
| :--- | :--- |
| $O(\log_3 N)$ | $O(1)$ |

**Важно:** Въпреки че $\log_3 N$ изглежда по-малко от $\log_2 N$, тернарното търсене извършва повече сравнения на всяка стъпка от двойчното търсене. Затова на практика Binary Search обикновено е по-бърз.

## 4. Jump Search

**Концепция:** Скоковото търсене е средно между линейното и двоичното. Работи върху сортиран масив и действа на принципа „скок“: вместо да проверяваме всеки елемент, скачаме с фиксиран размер `step` (най-често $\sqrt{N}$). На всеки скок сравняваме търсения елемент с елемента на текущата позиция:

* Ако `target ≥ a[j]` — скочиме напред.
* Ако `target < a[j]` — скочили сме твърде далеч и започваме **линейно** обхождане назад/напред в последния проверен блок, за да намерим точната позиция.

Анимация на Jump Search за елемент `36` в масива `{1, 4, 9, 16, 25, 36, 49, 64, 81}` ($N = 9$, $\text{step} = 3$):

![Jump Search анимация](images/jump_search.svg)

Сложност:

| време (най-лош) | памет |
| :--- | :--- |
| $O(\sqrt{N})$ | $O(1)$ |

## Кратко сравнение

| алгоритъм | сортиран масив | време (най-лош) | памет |
| :--- | :--- | :--- | :--- |
| Linear Search | не се изисква | $O(N)$ | $O(1)$ |
| Binary Search | да | $O(\log_2 N)$ | $O(1)$ |
| Ternary Search | да | $O(\log_3 N)$ | $O(1)$ |
| Jump Search | да | $O(\sqrt{N})$ | $O(1)$ |

* **Сортиран масив** → Binary Search (най-добър).
* **Несортиран масив + едно търсене** → Linear Search.
* **Много търсения върху несортиран масив** → сортираме веднъж, после Binary Search.
